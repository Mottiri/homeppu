# Development Workflow - 役割分担プロセス

## 概要

全ての開発作業は以下の4つの役割を順に実行すること。
ユーザーからの明示的な指示がなくても、このフローに従って作業を進める。

---

## 役割定義

### 1. 全体管理者（Overall Manager）

**担当:** メインの会話コンテキスト（Plan モード + Explore エージェント）

**責務:**
- アプリ全体の概要・仕様の把握
- CONCEPT.md / FEATURES.md への準拠管理
- プロジェクト構造の把握
- ユーザーとの要件議論・方針決定
- 最終承認後、全体の状態を把握・更新

**入力:** ユーザー要件
**出力:** 方針・スコープの決定

### 2. 機能管理者（Feature Manager）

**担当:** Task(subagent_type=Plan) エージェント

**責務:**
- 機能単体の詳細仕様把握
- セキュリティ・依存関係・運用観点の分析
- 詳細設計書の作成と更新（docs/ に保存）
- 実装後の検収（設計書通りか、考慮漏れはないか）

**入力:** 全体管理者からの方針
**出力:** 詳細設計書（Markdown）

### 3. 実行者（Executor）

**担当:** Task(subagent_type=general-purpose) エージェント

**責務:**
- 機能管理者が作成した設計書に忠実にコードを実装
- 設計書に無い判断が必要な場合は機能管理者に確認を求める

**入力:** 詳細設計書
**出力:** ソースコード

### 4. レビュワー（Reviewer）

**担当:** codex-review スキル + Task(subagent_type=general-purpose) エージェント

**責務:**
- 運用・開発観点でのコードレビュー
- セキュリティ上の問題チェック
- 他機能へのデグレ確認
- 無駄なコード・重複の検出
- 指摘があれば実行者に差し戻し
- 指摘がなければ機能管理者へ成果物を渡す

**入力:** ソースコード
**出力:** レビュー結果（OK / NG + 指摘事項）

---

## 実行フロー

```
ユーザー
  ↓ 要件・提案
[1. 全体管理者] 要件の議論・方針決定
  ↓ 方針・スコープ
[2. 機能管理者] 詳細設計書を作成（docs/ に保存）
  ↓ 設計書
[3. 実行者] 設計書に基づいてコード実装
  ↓ ソースコード
[4. レビュワー] コードレビュー
  ↓ NG → 実行者に差し戻し（修正 → 再レビュー）
  ↓ OK
[2. 機能管理者] 成果物の検収
  - 設計書通りに実装されているか
  - 考慮漏れはないか
  - 必要なら設計書を更新
  ↓ NG → 実行者に差し戻し（指摘内容付き）
  ↓ OK
[1. 全体管理者] 全体観点での最終確認
  - CONCEPT.md / FEATURES.md との整合性
  - 他機能への影響
  - プロジェクト全体の状態を更新・把握
  ↓ NG → 機能管理者に差し戻し
  ↓ OK
ユーザーへ最終報告
  - 実装内容の説明
  - リスク・注意点
  - 今後詰めるべきポイント
```

---

## 成果物の流れ

| フェーズ | 入力 | 出力 |
|---------|------|------|
| 全体管理者 | ユーザー要件 | 方針・スコープ |
| 機能管理者 | 方針 | 詳細設計書 |
| 実行者 | 設計書 | ソースコード |
| レビュワー | ソースコード | レビュー結果 |
| 機能管理者(検収) | コード + 設計書 | 検収結果・設計書更新 |
| 全体管理者(最終) | 検収済みコード | 全体状態把握・最終報告 |

---

## 差し戻しルール

- **レビュワー → 実行者:** 指摘事項を明記して差し戻し。修正後に再レビュー。
- **機能管理者 → 実行者:** 設計との乖離・考慮漏れを明記して差し戻し。
- **全体管理者 → 機能管理者:** 全体整合性の問題を明記して差し戻し。設計の見直しから再実施。

## 注意事項

- 各エージェント間の情報受け渡しは、メインのClaude（全体管理者）が仲介する
- 設計書は `docs/` 配下にMarkdownで保存し、エージェント間で参照可能にする
- このフローはユーザーの明示的な指示がなくても自動的に適用する
- 軽微な修正（typo修正、1-2行の変更等）の場合は、全体管理者の判断で簡略化してよい
